# Close-Tab Discard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development, with the owner-approved Sol 6.1 Medium implementation and Astra High review split. Implement after quota publication in the current isolated checkout; no extra worktree or mixed quota edits. No extra agents without authorization.

**Goal:** Qualified normal tab close requests exact preparation discard; tab switching and reload preserve active work, including latest committed PDF/compose edits.

**Architecture:** Add ephemeral local checkpoints first. Then register exact preparation manifests and send a small authenticated close command into a durable idempotent inbox that delegates to existing abandonment/cleanup fences. No heartbeat-based deletion or cloud saved-editor project.

**Tech Stack:** Existing TypeScript/React, sessionStorage/IndexedDB/WebCrypto, Worker, Supabase/PostgreSQL, Vitest and Playwright.

**Spec:** `docs/superpowers/specs/2026-10-26-close-tab-discard-design.md`.

## Constraints and review focus

- Close means discard; another tab/minimize/other app means keep; F5 means resume. Visibility, blur, idle age and missing heartbeat are never discard authorization.
- Latest unsaved PDF state currently exists only in memory. Checkpointing is required, not an already-completed capability. No editor JSON/cloud project upload is introduced.
- Same-job resume already exists; latest PDF/separate-compose/raw-input resume is a genuinely new Task1 capability. Keep those claims and Task2 close-cleanup evidence distinct. Record actual post-quota baseline before implementation; reviewed quota source `a08535d` is not lifecycle qualification.
- Actual Draft/Sent/uncertain attempts, admitted work and exact receipt/history safeguards remain. No blanket old-job cleanup or automatic provider action.
- Browser cannot guarantee close detection or keepalive delivery. Missing/ambiguous signals preserve work; timeouts must not delete a slow reload.
- Main failure cases: final edit immediately followed by reload; cancelled reload marker then real close; lost close response; late old-epoch close after resume; close racing create/upload/save/send. Each is covered below.

**Interfaces:** `CheckpointScope={actorId,authTabId,tabSessionId,workspaceOwnerId,region,preparationId,jobId,jobRevision,sourceFingerprints}`. Actor is stable `session.user.id`; authTabId is the existing authentication storage key, not access token. `initializePreparationTab({actorId,authTabId,arrival,approvedAuthReturn})` creates a fresh preparation ID/key for non-reload/copied-opener entry and preserves only verified reload/approved same-tab return. Ambiguous clone identity stays protected/read-only until a distinct server claim. Task2 adds tombstone/claim admission; Task1 must not silently merge copied tabs.

`openCheckpoint(scope):Promise<CheckpointHandle>` exposes `appendSmall(patch,expectedRevision):number`, `commitLarge(patch,assets,expectedRevision):Promise<number>`, `restore():Promise<CheckpointState|null>`, `clear():Promise<void>`. Patch carries schema version, base/result local revisions and concrete changed fields/pages/history, not a geometry command. `CheckpointState` covers bounded content/history, selected Account/page/layout and explicit raw inputs; no arbitrary screen state/cache/send replay/test recipients/credentials. The editor-local adapter provides synchronous `acceptSmall(transition):boolean` and a separate serialized busy `acceptLarge(transition):Promise<boolean>`; both fence source/local revision and update project/history/review invalidation once after persistence. Existing boolean commit callers remain boolean.

Decision/status updates happen only after implementation.

**Interfaces:** Fixed same-origin `/api/documents/tab-sessions` register/claim/resume returns acknowledged `{sessionId,epoch,manifestRevision}` for exact members or registered `{commandKey,payloadDigest}`. `DocumentCreateInput` carries that admission tuple in both `CreateDocumentDialog`, `BatchRoute.createEntries` and replacement creates. A private/service-only create-admission RPC validates actor/scope/payload and session state, calls `ar_document_create_v5`, and binds the resulting job in one transaction under the same locks as claim/close. Frontend attach-after-create is not the admission contract.

`POST /api/documents/tab-sessions/{sessionId}/close` accepts only `{commandId,epoch,manifestRevision}` ≤2 KiB. After actor authorization, lookup same command/identical body before current epoch checks; return accepted receipt on response-loss replay. Mutated replay or new stale command gives409. Return `{commandId,status:'accepted'|'processed',outcomes}` after durable inbox commit. Outcomes have terminal `discarded`/`protected` and retryable `pending` only for admitted generation/upload/save. Accepted definitive close cannot reopen. Frontend `attachPreparationLifecycle({scope,getToken,manifest})` owns one listener set; `getToken` reads a current ref, never identity or stale closure. Disposal alone never abandons.
