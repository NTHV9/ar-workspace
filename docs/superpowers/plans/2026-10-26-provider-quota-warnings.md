# Provider Quota Warnings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Use subagents only when separately authorized. Steps use checkbox syntax for tracking.

**Goal:** Show administrator-only provider quota warnings at Cloudflare 80% and Supabase 50%, while counting usage without application quota suspension.

**Architecture:** Separate provider usage evidence from the existing atomic operation ledger. Make SQL quota checks warn-only while retaining technical guards, then add private verified snapshots, authenticated administrator endpoints and UI. Provider display uses the full actual included quota; separate administrator Alert at % settings persist with atomic revisions. Supported automatic Cloudflare reads can follow after scoped credential authorization; no Supabase billing API is invented.

**Tech Stack:** Existing React/Vite/TypeScript, Cloudflare Worker and Supabase/PostgreSQL; existing Vitest, Playwright and synthetic PostgreSQL runner. No new dependency or paid service.

**Spec:** `docs/superpowers/specs/2026-10-26-provider-quota-warnings-design.md`.

## Global constraints

- Cloudflare defaults to **80%**, Supabase **50%**. Admin can save integer Alert at % from 1–100 per provider with atomic revisions/idempotency. The displayed denominator is always the full actual included provider quota.
- Quota threshold/full quota/telemetry unavailability never suspends employee work; counts continue.
- Quota alerts/details are administrator-only for authenticated `ar@katathani.com`; no new mail mechanism.
- Preserve auth, per-file content/size/SHA checks, atomic concurrency, idempotency, uncertain-upload and integrity/recovery safeguards.
- No auto-change of provider spend cap, subscription, paid plan or retention/deletion policy; no secrets/raw provider/customer data in Git or browser.
- Unknown is null, never zero; actual provider scope/cycle/source/time/unit must accompany each provider metric. Managed file transfers remain a separate app diagnostic.
- Implement with forward migrations; preserve all existing reservation/receipt/history rows.

## Review focus

1. Staff actor remapped to workspace owner must not gain administrator billing access (Task 2).
2. A provider snapshot at a cycle boundary or with one failed metric must not imply a new zero/healthy period (Task 2).
3. Removing UI quota denial must also remove SQL admission and insert/update-trigger denial (Task 1).
4. A lost upload response above full quota must retain one dispatch and recover through exact bytes (Tasks 1 and 3).
5. Deployment must not reintroduce quota suspension or overwrite unrelated live bindings during fallback (Task 3).
