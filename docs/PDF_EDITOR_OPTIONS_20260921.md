# Free PDF editor options — 21 September 2026

Status: research only. Official documentation and public source were inspected; a synthetic local row-model probe was run, but no replacement editor was installed, integrated, deployed or tested. No customer PDF was uploaded. The owner's latest constraint is **no additional cost**. Paid SDKs, trials, and paid cloud services are excluded.

## Recommendation

**Evaluate BentoPDF's free native text editor first.** It is the strongest verified candidate here for changing existing PDF text inside the browser. It is an application/source adaptation, rather than a proven drop-in React SDK. Its AGPL terms must be accepted and preserved; this research does not change this project's license. **Do not replace the current editor with EmbedPDF on the assumption that FreeText annotations mean original-text editing.** For structured Statement rows, pdfme is a separate template-generation option; it does not automatically turn an OPERA PDF into an editable table. Sources and limits follow.

| Option | Free route and runtime | Existing PDF text | Complete invoice-row insertion |
| --- | --- | --- | --- |
| **BentoPDF 2.8.8** | AGPL-3.0; static browser application; no mandatory paid service or key found | Shipped native text/paragraph editing, with font matching and reflow | **Unproven.** Paragraph/object duplication is not semantic table-row insertion |
| **EmbedPDF stable v2** | MIT viewer; PDFium has its own license; browser WASM | Verified FreeText annotations and redaction; no shipped original-text editing UI established | No verified table-row editor |
| **pdfme** | MIT; browser generator and embeddable Designer/Form | Edits schema fields over a fixed base PDF, or generates a new template-based PDF | Yes for its own table schema; not recognition/reflow of arbitrary source-PDF tables |
| **PDF.js + pdf-lib** | Apache-2.0 / MIT; browser libraries | Rendering plus forms/drawing; pdf-lib explicitly lacks ordinary page-text edit APIs | Requires the app's own structural interpretation and editing implementation |

## BentoPDF: promising, genuinely available free, needs a bounded proof

- The official **v2.8.8 release** introduces editing actual PDF text, paragraph reflow, font/style controls, and image/object manipulation. It explicitly warns that complex PDFs can expose bugs. Access to installed local fonts works only in Chromium browsers such as Chrome/Edge. These are vendor claims, not results on Katathani documents. [Release notes](https://github.com/alam00000/bentopdf/releases/tag/v2.8.8)
- The native editor is in the public repository: `src/js/editcore/app.js`, `core.js`, and supporting content-stream code. The current `core.js` calls a native `_ec_commit_paragraph` engine operation; this is materially different from only placing a FreeText annotation. Inspected application commit: `72d20bba092dbf4c293767086196c77f5f4519f0` (17 September 2026). [Editor source](https://github.com/alam00000/bentopdf/blob/72d20bba092dbf4c293767086196c77f5f4519f0/src/js/editcore/core.js), [UI source](https://github.com/alam00000/bentopdf/blob/72d20bba092dbf4c293767086196c77f5f4519f0/src/js/editcore/app.js)
- Its editor loader imports the vendored `bentopdf-pdfium` package and resolves a local `editcore.wasm` asset. The public packaging workflow creates that engine package with an AGPL-3.0 declaration; its engine fork is also public, including C++ editcore source. This supports a self-hosted browser deployment without a document-processing server or paid engine call. [Engine loader](https://github.com/alam00000/bentopdf/blob/main/src/js/editcore/engine-loader.js), [Engine packaging](https://github.com/alam00000/bentopdf/blob/main/.github/workflows/update-bentopdf-viewer.yml), [Public engine fork](https://github.com/alam00000/bentopdf-pdfium-viewer)
- Official instructions support static hosting, and the app describes all PDF processing as client-side. Adapting the editor into the existing Cloudflare static assets is therefore technically plausible; it has **not** been built or measured here. Existing hosting bandwidth, browser RAM, integration, and maintenance remain real resource costs. Other Bento tools optionally load large dependencies from CDNs; a narrow editor deployment should not import the whole toolkit by default. [Static hosting](https://github.com/alam00000/bentopdf/blob/main/STATIC-HOSTING.md), [Runtime and deployment documentation](https://github.com/alam00000/bentopdf#readme)
- The free code is **AGPL**, not MIT. The current licensing page says no license key is needed and paid-source delivery is identical to the public source, while requiring source disclosure for its free deployment/integration route. It also states producer/copyright metadata expectations. Repository licensing prose and the live website differ on the wording for internal tools; inspect the exact adopted release's LICENSE and integration obligations before adopting. Free does not authorize silently relicensing this app. [Current licensing page](https://www.bentopdf.com/licensing), [Repository LICENSE](https://github.com/alam00000/bentopdf/blob/main/LICENSE), [Repository licensing note](https://github.com/alam00000/bentopdf/blob/main/docs/licensing.md)
- Source has fallback-font loading, including Thai detection and a configurable font base URL. This gives a practical mechanism for missing glyphs, **not a guarantee of original-font fidelity** or correct Thai shaping on every PDF. Missing glyphs still require suitable font bytes. [Font loader](https://github.com/alam00000/bentopdf/blob/main/src/js/utils/font-loader.ts)

**Unknowns to prove before selection:** OPERA font subsets and new Thai/Latin glyphs; sparse Reference/Debit cells; multi-page row insertion with totals/footers; selectable text after saving; layout fidelity; undo; exact edited-byte export back to the private preparation workflow. No official table-row insertion capability was found in the inspected editor documentation/source. No documented stable React embedding or save-back API was established. An iframe or extracted component would need an explicit private-byte bridge and application-owned save handling.

## EmbedPDF: free viewer does not establish the requested replacement

The official stable v2 repository is MIT licensed and describes annotations, redaction, search, selection and viewing. Its Annotation plugin calls FreeText a text-box annotation. Native invoice text is a different content type. An open issue requesting PDF text editing contains the maintainer's explanation of subset-font glyph limitations; it is an idea discussion, not a shipped feature promise. [v2 source and feature list](https://github.com/embedpdf/embed-pdf-viewer/tree/v2), [v2 LICENSE](https://github.com/embedpdf/embed-pdf-viewer/blob/v2/LICENSE), [Annotation documentation](https://www.embedpdf.com/docs/react/headless/plugins/plugin-annotation), [Text-editing request and maintainer response](https://github.com/embedpdf/embed-pdf-viewer/issues/94#issuecomment-3202154464)

Version matters: current `main` warns that **v3 is not recommended for production**, while its licensing map has changed to Apache-2.0 for SDK packages. The separate CloudPDF server is FCL and requires a valid license to run; it is excluded from this no-cost recommendation. Do not combine the v2 website's MIT statement with v3/cloud server terms. [Main README](https://github.com/embedpdf/embed-pdf-viewer), [Main licensing map](https://github.com/embedpdf/embed-pdf-viewer/blob/main/LICENSING.md)

## pdfme and the current library boundary

pdfme's MIT library provides browser generation and an embeddable template Designer/Form. Its model explicitly divides a fixed `basePdf` from editable schemas; the cloud service is optional. Table schemas support columns, rows and page breaks when using a blank page definition. Existing-PDF backgrounds keep their original pages fixed and do **not** get automatic dynamic layout/page breaks. This makes pdfme relevant to system-generated Statements, not a direct arbitrary OPERA-PDF editor. [Getting started](https://pdfme.com/docs/getting-started), [Table behavior](https://pdfme.com/docs/tables), [Supported features and MIT statement](https://pdfme.com/docs/supported-features)

PDF.js is a PDF reader/rendering platform, and pdf-lib's own limitations say it has no APIs for removing or editing ordinary page text outside form fields. Custom fonts can cover new Unicode characters when the font contains them. Consequently, the app's current row reconstruction and native-text rewrite behavior sits above these libraries and cannot be assumed to become reliable by changing their viewer component alone. [PDF.js repository](https://github.com/mozilla/pdf.js), [pdf-lib limitations and fonts](https://github.com/Hopding/pdf-lib#limitations)

Use synthetic examples first: one sparse OPERA-like row with blank Reference/Debit, one subset-font PDF requiring new characters, and one multi-page table. Run the free Bento native editor from self-hosted assets; test editing, save/reopen, and preservation of untouched content. Treat full-row insertion as a separate pass/fail requirement. Only then use authorized private originals. Keep preview acknowledgment, private storage, and the exact reviewed-byte handoff owned by Katathani AR; an editor change must not write accounting data.

## Current missing-column behavior: locally verified

The current `rowGeometry` uses the first physical text band of the selected logical row as its template (`src/pdf/row-geometry.ts`). `insertRow` clones only those template runs (`src/pdf/use-native-editing.tsx`); it does not define cells from all table headings. A synthetic five-column example with a sparse credit row and a description continuation returned `generatedFields: 3`, positions `[20, 90, 360]`, `missingReference: true`, `missingDebit: true`, and `separable: true`. The same shape can therefore pass the insertion boundary check while omitting both empty fields. No application code or data was changed by this probe.

The screenshot's red wording is the **delete-row** overlap guard. That and occasional add-row rejection are separate from the reproduced missing-column issue; the actual customer PDF has not been used to reproduce the overlap geometry. A replacement reader/editor alone does not define the five accounting columns. The app should own a complete Date/Description/Reference/Debit/Credit row model, including empty cells, regardless of the PDF engine chosen.

## Free desktop alternative and web-hosting distinction

ONLYOFFICE Desktop Editors is a free local office suite with PDF text/object editing. The official PDF guide describes detecting editable text/object regions and modifying recognized text; it does not establish automatic five-column row insertion in an arbitrary OPERA invoice. It is a useful separate-program fallback. An import-back/review workflow in Katathani AR would still need implementation. [Desktop product](https://www.onlyoffice.com/desktop), [PDF editing guide](https://helpcenter.onlyoffice.com/docs/userguides/pdf_editor/EditPDF.aspx)

ONLYOFFICE Docs Community can be self-hosted without a license fee under AGPL, but it requires a Document Server and related infrastructure; it is not a static browser bundle that can simply replace the current Cloudflare-hosted component. Its licensing/source/branding terms and resource requirements must be considered separately from the free desktop program. No server purchase or deployment is proposed under the owner's zero-additional-cost constraint. [Edition comparison](https://www.onlyoffice.com/compare-editions), [Community licensing FAQ](https://helpcenter.onlyoffice.com/docs/faq/docs-community.aspx), [Server requirements](https://helpcenter.onlyoffice.com/docs/installation/docs-community-sys-reqs-windows.aspx)

## Decision boundary

The recommended next step is a local, disposable BentoPDF proof, subject to its free-license obligations, alongside a five-column table-model check. Passing paragraph editing alone is insufficient. pdfme is a candidate for app-generated Statement tables, not authorization to replace native OPERA Invoice/Folio source generation. No software was selected for production, no paid service enabled, and no source-sharing or license change authorized by this research.
