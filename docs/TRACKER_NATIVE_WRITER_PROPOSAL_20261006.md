## Limits that the plan must preserve

Range protection alone cannot exclude owners or whole-file replacement by an editor. Apps Script LockService protects cooperating code sections, not independent human or desktop writers. A database lease serializes AR web workers only. Read-before-write or post-write conflict detection is not atomic conditional protection. [Google range-protection guidance](https://support.google.com/docs/answer/1218656), [Apps Script LockService](https://developers.google.com/apps-script/reference/lock/lock-service), [owner protection behavior](https://developers.google.com/apps-script/reference/spreadsheet/protection#canedit).

If web, desktop and humans use the same owner identity, file ACL cannot distinguish these clients. A quiet window with that identity is a cooperative pilot, not an enforced guarantee. No automatic native enablement or completed conflict-safe acceptance may be claimed from that pilot.

## Proposed operator-controlled pilot

1. Keep actual Sent dates queued by exact Hotel + Account + Invoice. An operator selects a small batch; no auto-send and no general native write flag.
2. After the daily updater finishes, stop its launch/schedule temporarily and verify no upload is still running. The executable stays unchanged. Arrange a short staff editing/sorting pause.
3. Read and review every effective file-level writer, including domain/group/inherited access and owner/client use. If permission exclusion is proposed, obtain separate exact approval and prepare a complete restoration manifest first. Do not silently revoke domain or staff access.
4. Record the window owner, exact file, selected immutable Sent IDs, expiry and operation phase privately in the web database. Add no sheet tabs, columns, locks or metadata.
5. Freshly resolve each invoice's hotel/account/folio/source identity and current row. Review the exact R/U/V/W dates, first-billing floor, expected cell values and conflicts. Any ambiguity or competing source change holds that invoice.
6. Only after an explicitly accepted pilot, write the selected date values in one bounded Sheets batch. Preserve formulas, formats and unrelated cells. Verify date/identity readback and unaffected feature baseline. A timeout becomes uncertain; never resend or blindly repeat the write.
7. Release the window only after a known result. An expiry must not release other writers while a provider request is in flight or uncertain. Restore only exact permissions actually changed after revision review; never restore the entire workbook over a changed source.
8. Resume the existing updater and check its next publication. Any reverted date becomes a visible conflict, not an automatic overwrite or financial settlement.

This pilot requires cooperation from shared-owner clients. It is not sufficient for unattended conflict-safe writeback under the unchanged writer model.
