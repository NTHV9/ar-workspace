# OHIP Report search — complete operation review, 2026-09-09

Scope: all 33 matched operations across seven modules, supplied from the coordinating task's inspection of the original Report search tab. That task observed each row's method/path and available Info description in the live portal DOM. Five Report Configuration rows had no substantive Info description; their purposes below are grounded in official schemas and summaries, not invented portal text. This independent review read the published request/response contracts. No Execute/Try It, service execution, report generation, email, configuration mutation, subscription, key access, or deployment occurred.

## Fields inspected beyond operation names

`cashierClosureReportsList.cashierReportList` contains `cashierReportType` strings: Cash, Check, ForeignCurrency, CreditCard, Miscellaneous, ArSettlements, DepositTransfers and Shiftdrop. The response description says it indicates applicability based on payment posting types. It provides no per-item file name, output ID, base64 bytes or download URL. Generic top-level links do not establish an AR report mapping without an actual documented relation. The apparent new candidate is therefore a category list, not the missing Statement output route.

`getFolioReport` is materially different: `folioReportResultType.folio` explicitly declares a PDF in byte-format string. Its criteria remain Hotel/reservation/window/bill/type/date/reference currency. This is the only reviewed Report search operation with an explicit PDF success field, and it concerns the already known reservation Folio transport. It does not establish multi-Invoice selected native Statement output.

`configGenericReportType.printReport` exists and must not be overlooked. Its `printReportType` describes printer/email/fax destination, copy count and sent flag; `destination` is described as the default destination, with only Printer/Email/Fax enum values. Generic-report operation inputs otherwise describe saving report setup, default parameters, templates/data sources and module metadata; outputs are setup or status JSON. These fields do not prove standalone execution, a preview/PDF-return mode, native selected-Invoice parameter binding, or safe runtime behavior. No configuration write was attempted.

`reportType.customizedRtfAttachId` is explicitly the customized RTF template attachment, not the rendered PDF attachment. `formToRun` identifies the parameter-collection form. `dataSource` and `dataSourceType` concern the report's data source; `externalReportUrl` is configurable external-source URL information and must not be treated as permission to send credentials. Existing real template metadata had no external URL, and no new service response was obtained here.

The bounded search adds complete coverage of all 33 Report matches but no genuinely new native Internal Statement PDF execution/download contract. The unresolved contract remains how to execute the actual native template with the verified selected Invoice context, retrieve its output using documented identity, and sequence that with print-history processing. This is not proof that an additional Oracle API cannot exist outside the inspected results.
