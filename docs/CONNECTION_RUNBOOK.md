## Collection selection guard

Invoice rows retain `compressed`, `parent_invoice_no`, verified `parent_invoice_id`/`parent_open`, and `collection_role`. Existing/unresolved rows start unverified. `collection_selectable` is generated by PostgreSQL from a verified standalone/parent role and positive source open balance; callers cannot set it. A compressed child is never independently selectable, even when its source amount remains positive and its parent is zero. Original/open monetary columns are preserved.

`POST /api/collection/validate-selection` checks the existing allowlisted login, validates one Hotel + Account and up to100 distinct IDs, and calls `ar_validate_collection_selection` with the user's token/RLS. It ignores client balances/roles/eligibility flags. Missing, cross-scope, child, nonpositive or unverified rows reject the entire selection. This is a snapshot relationship preflight, not a send operation or a guarantee of credit terms/recipients/document readiness. Future Billing/Send code must recheck this guard server-side at action time; it must not trust an earlier browser result. No Gmail sending is enabled.
